- (constraint) Herite de la spec : le noyau est Apache-2.0 et ne lie jamais QGIS ; l'extension est GPL parce que QGIS l'est ; les deux communiquent a distance de bras, par processus separe. Non negociable (CLAUDE.md 2.2, 2.3).
- (constraint) Herite de la spec : aucune dependance GPL ou LGPL dans le noyau, liaison statique et transitivite comprises. Ni GEOS, ni DuckDB spatial. Licences admises dans le noyau : MIT, Apache-2.0, BSD. GDAL, a licence agregee, est audite avant toute adoption.
- (constraint) Herite de la spec : le noyau se lance, s'execute et passe ses tests sans QGIS installe (CAP-13, Done when 4). C'est ce qui fonde l'argument juridique de distance de bras et ce qui rend la V2 autonome possible. Toute dependance du noyau envers QGIS est un bug.
- (constraint) Herite de la spec : agent-first. Toute action utilisateur passe par une commande du registre ; aucune logique metier dans l'extension (CAP-6). Chaque commande porte soit une implementation Rust, soit une delegation declaree a QGIS, jamais les deux et jamais implicite.
- (constraint) Herite de la spec : hors ligne total. Aucune fonction du MVP n'emet de requete reseau, ni dans le noyau ni dans l'extension, et la preuve est automatique et non une lecture de code (CAP-1). Le reseau ne sert qu'a brancher une IA externe optionnelle.
- (constraint) Herite de la spec : le projet est un projet QGIS ; le noyau n'invente aucun format de projet. Le journal rejouable (CAP-7) est ecrit a cote du fichier de projet, et deplacer l'ensemble sur un autre poste restitue projet et journal (CAP-10).
- (constraint) Herite de la spec : les quatre points d'entree (extension QGIS, CLI, agent local, serveur MCP) appellent le meme registre et un meme appel y donne le meme resultat (CAP-6, CAP-8). Le produit garde toutes ses fonctions sans IA externe branchee.
- (constraint) Herite de la spec : les fichiers d'origine de l'utilisateur ne sont jamais modifies ni deplaces ; Cassini ne telecharge, ne catalogue et ne redistribue aucune donnee.
- (constraint) Herite de la spec : le depot public ne contient aucune fonction specialement concue pour l'usage militaire. Le module defense est un depot prive distinct, construit sur le noyau Apache-2.0 et non sur l'extension GPL - ce qui impose que la frontiere du noyau soit utilisable telle quelle par un tiers prive.
- (constraint) Herite de la spec : le noyau se compile sur Windows, macOS et Linux ; l'extension cible les plateformes ou QGIS tourne. La recette automatique controle Rust, TypeScript et le Python de l'extension.

- (decision) La boucle d'execution vit dans le noyau. Le noyau planifie, dicte chaque etape a l'extension et journalise sa reponse ; l'extension est un executant sans logique metier, qui expose un jeu fixe de gestes QGIS. Binds : CAP-4, CAP-6, CAP-7, CAP-13. Previent : quatre boucles d'orchestration divergentes, une par point d'entree, ce que CAP-6 interdit ; et un journal a plusieurs auteurs, dont le rejeu ne serait plus fiable. - (decision) Consequence directe : le canal local porte les appels dans les DEUX sens sur une meme connexion - extension vers noyau pour la demande, noyau vers extension pour chaque ordre QGIS. Un canal question/reponse a sens unique est exclu. L'extension doit donc pouvoir recevoir un ordre sans figer la fenetre de QGIS.
- (direction) Audience du troisieme livrable : un collegue ou contributeur technique. Le rendu de fin sera une presentation de l'architecture avec schemas, lisible par quelqu'un qui pourrait contribuer au code - et non un memoire juridique ni un support de levee.
- (version) Verifie sur qgis.org/resources/roadmap le 2026-10-14 : versions supportees = 3.44.15 (derniere LTR de la serie 3.x) et 4.2.3 (version courante, Qt 6). QGIS 4.0.0 est sorti le 2026-03-06. La premiere LTR de la serie 4.x est 4.4.0, datee du 2026-10-30 sur la feuille de route - le billet d'octobre 2025 annoncait 4.2, le calendrier a glisse.
- (version) Verifie sur plugins.qgis.org/docs/migrate-qgis4 le 2026-10-14 : la compatibilite d'une extension se declare par qgisMinimumVersion et qgisMaximumVersion dans metadata.txt ; le drapeau supportsQt6 est abandonne. Une extension compatible 3.x et 4.x garde qgisMinimumVersion=3.xx et ajoute qgisMaximumVersion=4.99. Le shim qgis.PyQt fourni par QGIS masque la difference PyQt5/PyQt6.
- (constraint) Verifie sur gnu.org/licenses/gpl-faq le 2026-10-14 : la FAQ de la FSF nomme les tuyaux, les sockets et les arguments de ligne de commande comme les mecanismes normalement employes entre deux programmes separes, MAIS reserve le cas ou la semantique de l'echange est assez intime - echange de structures de donnees internes - pour que les deux parties soient considerees comme un seul programme. Consequence : l'argument de distance de bras repose sur la NATURE de ce qui circule, pas sur le choix du tuyau.
- (decision) Canal local : entree et sortie standard d'un processus enfant. L'extension lance le binaire du noyau et dialogue par stdin/stdout. Binds : CAP-13, CAP-1, CAP-8. Previent : une interface reseau ouverte sur la machine - qui rendrait la preuve zero reseau de CAP-1 negociable et declencherait une demande du pare-feu Windows - et un service fantome dont le cycle de vie divergerait de celui de QGIS. Choisi par le proprietaire le 2026-10-14 contre la socket locale et les fichiers d'echange. Cout assume et nomme : un client par processus, donc deux fenetres QGIS chargent deux fois le modele en memoire ; les gros binaires voyagent par chemin de fichier et jamais en octets dans le tuyau.
- (decision) Plancher QGIS : une seule extension pour les deux series, qgisMinimumVersion=3.44 et qgisMaximumVersion=4.99, via le shim qgis.PyQt. Binds : CAP-13. Previent : deux variantes d'extension a maintenir, et surtout la derive ou un contributeur importe PyQt5 et un autre PyQt6 dans le meme code. Motif : les bureaux d'etudes et collectivites visees restent sur une LTR pendant des annees, 3.44 est la derniere de la serie 3.x et sera installee partout en 2027. Choisi par le proprietaire le 2026-10-14. Repond a la question ouverte de la spec sur la version plancher.
- (decision) Regle induite par la FAQ de la FSF : le canal ne transporte que des messages publics et documentes - identifiants de commande, parametres a schema JSON, resultats types, chemins de fichiers. Jamais une structure de donnees interne du noyau, jamais un objet PyQGIS serialise. C'est la condition qui tient l'argument de distance de bras, la FSF reservant explicitement le cas d'un echange assez intime pour que deux programmes n'en fassent qu'un.

Six crates de fondation le sont, toutes en MIT OR Apache-2.0 : wbgeotiff 0.1.2 (474 telechargements, maj 2026-05-07), wbraster 0.2.1 (460), wbprojection 0.3.3 (15 772), wbvector 0.1.6 (14 726), wbtopology 0.2.1 (14 506), wblidar 0.1.3 (152). Reste a verifier par compilation d'un cas d'essai, comme la spec le demande.
- (constraint) Conventions deja etablies par le code existant, ratifiees et non reinventees : la crate s'appelle cassini-core et n'a AUCUNE dependance a ce jour ; les commentaires de documentation sont en francais et citent les paragraphes de CLAUDE.md ; les erreurs sont des enum typees par module (BasemapError), sans thiserror ni anyhow ; le refus est prononce a la construction et non a l'usage ; aucune troncature silencieuse - une lecture plus courte que demandee est une erreur nommee.
- (assumption) Tension relevee dans le code existant : basemap.rs porte la convention 'l'interface ne connait jamais le chemin du fichier, elle demande des plages d'octets', ecrite pour la coquille Tauri. Le virage l'inverse pour le vecteur - c'est QGIS qui lit les fichiers - et ne la garde que pour le terrain, ou le noyau lit le MNT lui-meme. A trancher explicitement dans le contrat, sinon deux moities liront les fichiers chacune de son cote.
- (decision) Charge utile du canal : des references par defaut (identifiant de couche QGIS, chemin de fichier relatif, denombrements, emprises, descriptions de champs), plus un petit nombre de geometries ponctuelles explicitement autorisees en GeoJSON (RFC 7946) - point d'observation, emprise, polygone de decoupe - parce que l'analyse de terrain en a besoin. Une couche entiere ne traverse JAMAIS : elle se designe, et au-dela du plafond on passe un chemin de fichier. Binds : CAP-13, CAP-11, CAP-3. Previent : la derive ou une moitie envoie des octets quand l'autre attend une reference, l'effondrement des performances des qu'une couche grossit, le retour de la geometrie dans le noyau, et la qualification d'echange intime que la FAQ de la FSF reserve. Choisi par le proprietaire le 2026-10-14.
- (decision) Consequence : il faut une commande qui DECRIT une couche - champs, types, echantillon de valeurs, denombrement, emprise, systeme de coordonnees - sinon l'agent planifie a l'aveugle, puisqu'il ne voit jamais les donnees. Elle est deleguee a QGIS.
- (decision) Rejeu : le journal enregistre pour chaque entree le chemin du fichier source RELATIF au projet (autorite), l'identifiant de couche QGIS (indice), et la taille et la date du fichier. Le rejeu resout par le chemin. Aucun chemin absolu n'est ecrit dans le journal, messages d'erreur compris. Binds : CAP-7, CAP-10. Previent : un journal qui casse des que le dossier change de poste - ce que CAP-10 exige pourtant - et un journal illisible par un humain. Choisi par le proprietaire le 2026-10-14.
- (constraint) Verifie mot pour mot sur plugins.qgis.org/docs/publish le 2026-10-14 : 'Don't include binaries' ; 'The size of the plugin package should not exceed 25MB' ; 'The plugin license is compatible with the GPLv2 or later' ; une dependance externe doit etre clairement declaree dans le champ About de metadata.txt ; le depot recommande QgsNetworkAccessManager pour tout acces reseau. Consequence fermee : le binaire du noyau ne peut PAS voyager dans l'archive de l'extension.

Binds : CAP-13, CAP-1, publication. Previent : deux ordres de recherche divergents, et toute tentation de reparer une installation par le reseau. Choisi par le proprietaire le 2026-10-14.

L'extension ignore ce qu'est un modele, elle affiche la liste. Binds : CAP-4, CAP-13. Previent : trois decouvertes de modele ecrites separement dans l'extension, la CLI et l'agent. - (decision) Preuve zero reseau cote Python : un test se branche sur le signal requestAboutToBeCreated de QgsNetworkAccessManager et verifie qu'aucune requete n'est creee pendant le chemin nominal de l'extension. Binds : CAP-13, CAP-4, CAP-6. Previent : un noyau plus recent qui immobilise tous les postes, et un agent qui propose une etape vouee a l'echec.
